# 执行面板

侧栏展示，要求在当前主对话框输入。复用已注册的 `execution-panel` MCP，不注册第二个服务，不为打开面板新建聊天、Agent 或 Goal。

## 开始和继续

- 对已授权的多步执行，先 `read_execution_plan`，已有计划则复用；没有时按主要成果初始化通常 4–8 个节点及验收要求。不要把方案讨论草稿或工具调用清单当成执行计划。
- 使用当前宿主精确任务身份；缺失时只用可靠的当前 `sessionId`，不猜最近聊天。
- 在实质执行时请求 `show_execution_panel`。用户明确选择手动打开、关闭本聊天面板或不要面板时，遵从其选择。本技能不声称用户已经设置全局偏好，也不主动写全局 AGENTS.md。
- 默认使用原生 MCP App，主对话继续输出。资源请求展开模式；工具成功不代表右栏已打开。宿主不支持或未展开时如实说明，不自动以网页替代。独立 preview 仅用于明确授权的开发调试。
- 右栏已打开就复用，让其独立刷新，不为每次更新重复打开。缺少 MCP 时说明连接不可用，不伪造进度。

## 更新计划

- 编号是当前 Plan `nodes` 数组的显示顺序，包含完成/取消项；更新时用稳定 `nodeId`。旧版本编号先核对历史。
- 主要节点开始、完成、受阻时 `report_execution_update`。结构、依赖或验收要求变化使用 `set_execution_plan`，附 `reason` 与当前 `expectedVersion`，保留历史，重新验证受影响完成项。
- 卡点、决定、分支、待验收使用稳定 issue ID；解决同一事项时复用 ID 并写 resolution。改变已有 kind 时带 reason 与 expectedVersion。
- 普通等待验收用 `verification`，不冒充 blocker；未解决仍不能标完成。`needsReview` 专指要求变更后的待修订。
- `dependsOn` 只描述依赖；多项真实执行、无阻塞且前置满足时才能显示并行。不要为演示伪造执行或启动 Agent。百分比是节点计数，不是工时或 Goal 完成承诺。

## @ 与干预

- 所有节点均可 @，不限卡点/验收；带入当前编号、稳定ID、状态、说明与验收要求。事项可单独引用。
- 只有宿主声明草稿能力、绑定当前聊天时才追加 `active + send=false`；否则复制。未确认不自动重试，重开不自动导入。不得把复制当送达，不新增侧栏输入框或自动发送接口。
- 导入的快照只是上下文。用户补充并发送要求后才执行；点击按钮本身不改变节点、请求或 Goal。
- 沿用已有原生 Goal，面板不控制其生命周期。只有用户明确要求才创建 Goal；暂停使用原生机制，不用面板数据冒充已暂停。
- “第 N 项完成后停下”是在验证该项后、开始下一主要节点前停下；立即停止用客户端停止入口。遗留请求处理一次并记录结果。
